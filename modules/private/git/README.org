#+title:    :private git
#+subtitle: magit tuned, the history and branch menus

* Description
Git for the power user, on Doom's =:tools magit=. Doom gives the status
buffer, the evil layer and the =SPC g= keys; this module adds:

- settings that show more and ask less: every menu argument visible
  (transient level 7), file buffers saved before status, word diffs in
  every hunk of a diff that is not large, dates instead of ages in the
  logs, the branch prompt
  sorted by date, file icons, the repository list on =~/projects=,
- a log you can read down: refs printed after the summary, not before
  it, so every summary starts at the same column; the graph's lanes in
  the theme's colours,
- a diff that shows what changed: tab width taken from the file's mode
  rather than assumed to be eight, indentation with the wrong character
  highlighted, the =^M= of a CRLF file hidden, the code's own syntax
  colours inside the hunks, nexenne's, when =delta= and =bat= are
  installed, the words that
  changed set apart from the hunk under the cursor, and each hunk's =@@=
  line naming the function it is in,
- git told what makes it pleasant, on the command line of the git magit
  runs, so nothing is set up by hand on a new machine (below),
- the repository's TODO and FIXME comments as a section in the status
  buffer, grouped by directory,
- a safety net: ~magit-wip-mode~ keeps work-in-progress refs before every
  commit, checkout and reset and after every save, so a botched rebase
  is one log away (=SPC g h L=),
- three menus in plain words: the hub, the history, the branches,
- a tag menu on =t=: a tag on the commit under the cursor, on any commit
  found by a word of its message or its hash, on a branch's head, or on
  HEAD, and one deleted here and on the remote at once; every prompt for
  a commit lists the latest ones, hash, date and subject, the one under
  the cursor first,
- what magit has no command for: change a commit's date or author,
  split a commit, uncommit, a branch from the fetched main, the merged
  branches swept, the diff and the log against main,
- =C-c C-t= in the commit buffer: the conventional subject with the
  scope read off the staged paths,
- the history of the function at point (=a= in the hub) and of the
  region's lines (=L= with a region), and the file as it was before
  (=v=),
- the Git chapter of the cheat sheet, =SPC h /= from any magit buffer.

* Keybindings
| Key       | Command                  | What it does                                                               |
|-----------+--------------------------+----------------------------------------------------------------------------|
| ~SPC g SPC~ | ~+git/menu~                | the hub: every day, menus, repos, tools                                    |
| ~SPC g h~   | ~+git/history~             | rewrite: reword, edit, date, author, split, drop, fixup, rebase            |
| ~SPC g n~   | ~+git/branches~            | make, switch, rename, delete, compare with main                            |
| ~C-c C-t~   | ~+git/commit-conventional~ | in the commit buffer: type(scope):                                         |
| ~t~         | ~+git/tag~                 | in magit: tag a commit by message or hash, a branch head, HEAD             |
| ~SPC t B~   | ~+git-blame-line-mode~     | the commit behind the current line at its end, on in code buffers under 1M |

Everything else is magit's own, under the keys evil gives it: =SPC g g=
status, then =s u= stage and unstage, =c= commit, =p= push, =F= pull,
=l= log, =d= diff, =b= branch, =r= rebase, =Z= stash, =x= discard,
=o O= reset, =%= worktree, =?= the dispatch. The cheat sheet's Git
chapter lists them by activity.

* Rewriting a commit that is not HEAD
=SPC g h d= (date), =SPC g h a= (author) and =SPC g h s= (split) reach an
older commit the way git does by hand: an interactive rebase that stops
at it (sed turns its =pick= into =edit=), the amend, and =rebase
--continue=. The working tree is stashed round it. The commits after it
are rewritten, as by any rebase, and their committer dates move to now;
their author dates stay. A rebase that stops on its way, a conflict,
is left for magit: =r r= continues, =r a= aborts.

* Conflicts
Doom turns ~smerge-mode~ on by itself when a file is opened with conflict
markers in it, and puts the commands on the localleader, where nobody
looks in the middle of a rebase. ~]n~ and ~[n~ move between conflicts as
they do in vim, and carry on into the next file that has one once this
buffer is clean; ~SPC g x~ (~x~ in the hub) is the menu for which side to
keep, with ediff and refine for the ones that are not obvious.

The menu names the sides by what they are. In a merge, a cherry-pick or
a revert the upper side is yours and the lower the change coming in; in
a rebase it is the other way round, the upper the branch rebased onto
and the lower your commit, and the menu says so. Keeping a side moves to
the next conflict with the menu still open. The base, the text before
either side changed it, is greyed out when the conflict does not show
it; every conflict magit's git makes does (=zdiff3=, below). Once a
file has no conflict left it is saved and the next file with one opens.
A resolution
made once is replayed when the same conflict comes back (=rerere=).

* Configuration
- ~+git-commit-types~: the types =C-c C-t= offers, the hook's list.
- ~+git-date-format~: how a commit's date is shown and read.
- ~+git-pick-commits~, 500: how many commits a prompt for one lists.
- The rebase menu's defaults, =--autostash --autosquash=, are set only
  when the menu was never saved (=C-x C-s= in it keeps your own).
- ~+git-delta-max-size~, 400k: past that a diff is painted the plain way,
  since delta is a process per diff and a release-sized one is not worth
  the wait. It is painted in magit's colours then; it lost them all
  before, delta's plain faces staying on.
- ~+git-refine-all-max-size~, 64k: magit, painting a diff itself (past
  delta's limit, or without delta), marks the changed words in every
  hunk up to this size, and in the hunk under the cursor past it, and
  never in a hunk past ~diff-refine-threshold~ (30 000 characters), as
  diff-mode does. Refining is what magit's painting costs: a 249 KB diff
  refreshed in 2.5 s refining every hunk, 0.8 s now.
- What the git magit runs is told, by =-c= on its command line, so
  =~/.gitconfig= stays yours, and a setting of your own there wins:
  =merge.conflictStyle=zdiff3= (=diff3= before git 2.35), =rerere.enabled=
  (which git then keeps on in that repository, outside Emacs too),
  =diff.algorithm=histogram=
  (the gutter's), =fetch.writeCommitGraph= (the ten latest commits of a
  150 000 commit history read in 0.5 s without the graph, at once with
  it), =log.graphColors= from ~+git-graph-colors~ (the theme's blue,
  magenta, cyan, green and yellow; no red, which reads as removed), and
  each file kind's diff driver from =gitattributes= in this module, with
  patterns for elisp and org that git lacks. The attributes file is not
  used over one of your own (=core.attributesFile=, or
  =~/.config/git/attributes=).
- magit-todos scans the tree once a minute at most, not at every
  refresh of the status buffer.
- ~+git-blame-max-size~, 1M: the blame turns itself on below it. It is
  one =git blame= of the whole buffer, taken in the background when the
  buffer has changed and the cursor rests, and read line by line from
  there; ~+git-blame-idle~ (0.5 s), ~+git-blame-column~ (40) and
  ~+git-blame-summary-length~ (50) shape it.
- =delta= has to be installed for the coloured diffs: =sudo zypper in
  git-delta=. Without it nothing breaks and magit paints its own way.
- Options, not installed: =forge= (issues and pull requests from magit;
  the =+forge= flag on =:tools magit= and a GitHub token in
  =~/.authinfo.gpg=, =machine api.github.com login USER^forge password
  TOKEN=). Magit 4.6's own syntax colours in diffs are left off: on
  this config's history they were slower than delta (453 ms against
  94 to refresh a 9 KB diff) and stopped on an org hunk.
- The files: =config.el= (settings, keys), =autoload/menu.el= (the three
  menus), =autoload/commit.el= (the subject, date, author, split,
  uncommit), =autoload/branch.el= (from main, delete merged, against
  main).
