#+title:    :private ui
#+subtitle: glyphs, dashboard and visual aids

* Description
- one more font fallback for arrows, technical and dingbat symbols, on top
  of the Nerd Font and emoji fonts Doom already maps,
- glyph helpers: insert an icon, insert it as elisp, or check the fonts,
- a dashboard with the name as an ASCII banner a ripple runs through,
  carrying a slow wave of colour, a greeting another module may register
  (the butler's), the date as it would be announced, and the entry points
  with their current keys; the same in a terminal,
- where you are, in code buffers: a header line with the project path and
  the symbol path, file > class > function, replaced by the first line of
  the enclosing function while that is scrolled off the top; the symbol
  outline at the side on ~SPC t o~; in the modeline, the line out of how
  many the buffer has, the column out of how many the line has, and how
  far through the buffer you are as a percentage, =228/1009:7/42  23%=, so
  the fringe is left to the git gutter and the diagnostics; the minimap on
  the right on ~SPC t m~, a copy of the buffer in a tiny font with the
  part on screen marked, taken again once the typing pauses, so moving and
  typing cost it nothing, and a click in it goes there; indent guides,
  ~SPC t i~ turning them off; diagnostics at the end of the line as well as in
  the popup, flymake underneath, which eglot reports into directly,
- the wheel stops at the end of a file, with its last line at the bottom
  of the window; it scrolled on until the window was empty. The keys
  still go past the end, as C-e does in Vim,
- Treemacs settings and documentation popups.

* The banner and the greeting
The banner spells out ~+ui-banner-name~, your login name unless
=config.el= says otherwise, in the letters of ~+ui-banner-font~: the
ascii9 figlet font, seven rows of seven columns a glyph, so a name is
drawn by laying its glyphs side by side when the dashboard is built
rather than kept as art.
~+ui-banner~ takes art of your own instead, one string per line, when
there is something better than a name to put up there. Either way it
stands in for Doom's banner widget, which is how the dashboard README
says to replace the banner in both the GUI and a terminal.

The banner is alive in two ways. A ripple rolls through it letter by
letter: each letter moves as one piece, a row up or down, so the word stays
readable while it sways; ~+ui-banner-ripple-letters~ is the length of the
wave in letters and ~+ui-banner-ripple-speed~ how far it travels per tick.
Behind that a wave of colour runs between the two theme colours in
~+ui-banner-gradient~ over ~+ui-banner-wave-steps~ shades, so it follows
the theme; on a theme that is not a Doom theme the banner keeps Doom's face
and only the ripple moves. The frames of the ripple and the runs of the
wave are computed once when the banner is drawn, since both repeat; a tick
picks its frame. One timer drives both, every ~+ui-dashboard-tick-interval~
seconds, and it runs only while a client frame shows the dashboard, not on
a daemon's terminal frame. ~+ui-dashboard-animate~ nil stops it.

Doom centres the dashboard down the window by padding it, and measures
the window with ~get-buffer-window~, which answers for the selected frame.
A child frame, the butler's bubble or a completion popup, is the
selected frame while the window hooks run for it, and the dashboard was
then padded for a seven row window: the centring was lost and, nothing
else resizing the real window, it never came back. A child frame
changing size says nothing about the dashboard, so ~+dashboard-resize-h~
is skipped while one is selected; the real frame's own resizes still
run it, margins and all.

The greeting is whatever ~+ui-dashboard-greeting-function~ inserts, given
the width to centre in; with the butler module on it is his, in his
bubble, and ~+ui-dashboard-tick-hook~, run in the dashboard buffer at
every tick with the ticks elapsed, is what keeps him blinking there. The
dashboard itself knows no module: nil and an empty hook show the date
alone. The bubble is drawn in characters, so the words keep the normal
size and are bold instead, face ~+ui-greeting~. A line below, the date is
announced the way it would be said, "Tuesday, the 15th of September 2026,
at 11:36", in English whatever the system locale, and the minute is kept,
face ~+ui-date~.

The dashboard can be scrolled, ~C-u~ and ~C-d~ or the wheel, when it is
taller than its window; Doom's habit of pulling the cursor back to the menu
after every command is set aside for scrolling commands. Nothing on it gets
selected or lit up: the cursor is hidden, the mouse does not highlight the
entries as it passes, and a drag selects nothing. Clicking an entry, or
~RET~ on it, still opens it.

A picture instead of the banner wants ~+dashboard-widget-banner~
back in ~+dashboard-functions~ and ~fancy-splash-image~ pointed at
it.

~]e~ and ~[e~ are ~next-error~, which walks whatever buffer last reported
errors. With flymake doing the checking, that is some compilation log
from an hour ago, and the key leaves the file altogether. Flymake says
in its own manual that it does not take ~next-error~ over and that one
should say so oneself, so a buffer flymake checks gets a
~next-error-function~ of its own and ~]e~ walks that buffer's diagnostics.

* Redrawing
Emacs redraws a window by laying out every line of it again unless it
can tell that only the cursor moved or only a line changed, and on a
full frame of C++ that layout is most of what a key costs. Two things
kept it from telling, and one made the modeline dear:
- The theme draws the current line's number unlike the others, bright on
  hl-line's band, and Emacs gives up every shortcut when those two faces
  differ: each redraw laid out the whole window, even one that follows a
  timer or a server message and changes nothing. Where Emacs looks, the
  two faces are the same now, and the theme's look comes back through a
  remap in the buffers where hl-line is on; there a change of line always
  moves hl-line's overlay, which redraws the whole window anyway, so the
  bright number cannot stay behind on the line the cursor left.
- hl-line moved its overlay onto the current line after every command,
  even where it already was, and an overlay moved in place still counts
  as a change of the whole window. It moves only when the line does; and
  while a key is held, commands closer together than
  ~+ui-hl-line-repeat~ (70 ms, where KDE repeats every 40), the band and
  the bright number step aside in the window you work in and are back
  as soon as the key is let go. A held line move costs 1.4 ms, not 3.9.
- Doom's light modeline formatted its right half twice at every key, once
  only to measure it, and eglot's piece of it is a quoted cl-loop the
  interpreter expanded afresh each time. Once, and compiled once, it
  takes 70 microseconds instead of 200. The pieces that loop formats,
  the server's errors, pending requests and progress, are quoted code
  as well, compiled once too.

Measured with the key held, in a C++ file with clangd attached: a line
move 20.6 ms to 10.2, a move along the line 20.6 to 2.7, a keystroke 24.8
to 12.5, a redraw that changes nothing 11.2 to 1.1.

Colouring had its own waste:
- Emacs 31 colours text as it comes on screen in chunks that end where
  hidden text starts, so that a folded subtree is not coloured for
  nothing. But org also hides the ~=~ and =~= around code and the
  brackets of a link, and each of those ended a chunk, widened again to
  whole lines: a line of the cheat sheet with ten of them was coloured
  twenty times. A chunk runs on through hidden text shorter than
  ~+ui-jit-lock-hidden-min~ (500 characters) and stops before a longer
  one, the body of a fold. A half page of the unfolded cheat sheet shown
  for the first time: 60 ms to 8; typing in it 6.4 to 4.7.
- When colouring a chunk takes in text before it, as a markdown code
  block does from the line typed on back to its first, jit-lock redraws
  the window a second time; now only when a window shows that text. Typing
  in a block whose start is above the window: 8.3 ms to 5.8.
- The header line's function is looked up again half a second after the
  typing stops, not at every key, where there is no syntax tree to ask:
  in cc-mode that walk was half of what a key cost. In a file Doom calls
  large it is not looked up at all; in a 2 MB header of declarations
  cc-mode walked back through them at every step, 130 ms a line scrolled.

* Configuration
- ~+ui-symbol-fallback-font~, "Noto Sans Symbols 2" by default.
- The minimap: ~+ui-minimap-width~ (16 columns), ~+ui-minimap-idle~
  (0.1 s before its marks follow), ~+ui-minimap-copy-idle~ (0.5 s after
  an edit before the text is copied again), ~+ui-minimap-colour-max-size~
  (1 MB, past which only the colours already worked out are shown), and
  the faces ~+ui-minimap-face~, ~+ui-minimap-region-face~,
  ~+ui-minimap-line-face~. It is not demap, Doom's: demap's minimap is an
  indirect buffer, which shares its text's change counters with the
  file, so every overlay the file moved redrew the minimap, 8 ms a key.
- ~+ui-current-line-number~: the current line's number as the theme
  draws it, taken from ~line-number-current-line~ whenever a theme loads.
- ~+ui-hl-line-repeat~, 0.07 s: commands closer together than this come
  from a held key, and hl-line steps aside until it is let go; 0 keeps
  the band on every line the cursor passes.
- ~+ui-jit-lock-hidden-min~, 500: hidden text shorter than this many
  characters is coloured with the text around it.
- ~+ui-flymake-eol-max~, 300: past that many diagnostics in a report,
  none is written at the end of its line; the underline, the fringe and
  the popup still show them.
- The fonts themselves are in =$DOOMDIR/config.el=; ~SPC h r f~ reloads them.
- Dashboard entries: ~+dashboard-menu-sections~.
