#+title:    :private ai
#+subtitle: A chat, Claude's terminal, inline actions and gptel

* Description
Four ways to work with an agent, all under =SPC l=; ~SPC l SPC~ is the hub
with all of it on the same keys.

- The chat, [[https://github.com/xenodium/agent-shell][agent-shell]]: Claude in a side panel, as in VS Code's extension.
  It is an Emacs buffer, so evil works on the transcript and on the prompt:
  ~RET~ in normal state at the prompt sends, ~v~, ~y~ and searches only read
  the transcript. The header shows the permission mode (Claude's own
  default, Manual), the model and the context used; ~C-<tab>~ cycles the
  mode. A tool that wants permission shows buttons, and point goes to them:
  ~y~ allow once, ~n~ reject and stop the turn so you can say what to do
  instead, ~!~ always allow, ~v~ view the diff, which opens in the editor
  window, not beside the chat. Elsewhere in the chat those keys are evil's.
  Once an edit lands, an open buffer of that file reloads, unless you
  have changed it.
  A new chat starts with nothing in its prompt but the region, dired's
  files or the error at point; ~SPC l @~ adds a mention of the file and
  lines, focus staying in the code. ~C-u SPC l n~ picks another agent.
- The Claude terminal, [[https://github.com/manzaltu/claude-code-ide.el][claude-code-ide]]: Claude Code's own TUI in vterm,
  the fallback. Keys go to Claude; ~C-z~ gives normal state to read and
  copy, where the keys that would edit the screen only say how to type, ~i~
  goes back to Claude's prompt and ~p~ pastes into it. ~SPC l t p~ writes a
  long prompt in a buffer of its own.
- Inline actions on the code: rewrite the region as a diff to accept or
  reject, explain, ask, a commit message. They go through gptel once it
  has a key, else through =claude -p= with the CLI's own sign-in, with no
  tools and no session kept.
- gptel (Doom's =:tools llm=): chat and context against the API, with
  read-only Emacs tools that stay inside the project.

The chat and the terminal both reach Emacs over MCP: xref, tree-sitter,
imenu and project from claude-code-ide, plus this module's own. The read
ones run without asking, as VS Code's IDE tools do: =emacs_editor_state=
(the file, point, the region and the diagnostics of the window you work
in), =emacs_last_compilation=, =emacs_project_todos=, and with the notes
module =emacs_notes_search=, =_list=, =_read=, =_links=. The rest ask first:
=emacs_build_project= (through the C++ kit when that module is on),
=emacs_org_add_todo= into the inbox, =emacs_notes_append= into today's daily
note, =emacs_notes_draft= for a new note under =capture/drafts=; they never
rewrite an existing note. A chat's or a terminal's tools work on its own
project, whatever buffer you are in, and open no file outside it. Your
home or any directory in it can be that project; / and the system's
directories are refused.

When a hidden chat or terminal waits for a permission or finishes, the
modeline says =AI PROJECT: permission= or =done= and a notification
appears; ~SPC l j~ goes there, on a chat to its button.

| ~C-c C-e~    | write a prompt in a buffer                   |

| ~C-<escape>~ | Escape to Claude                             |

| ~C-z~        | normal state to read and copy; ~C-z~ or ~i~ back |
| ~C-c C-t~    | vterm copy mode                              |

In normal state there ~d~, ~x~, ~c~, ~r~, ~u~ and their capitals do nothing,
~i a o I A O~ go back to Claude's prompt, ~p~ pastes into Claude; motions,
~y~ and ~s~ are as usual. In the prompt buffer ~C-c C-c~ sends, ~C-c C-k~
drops it, ~M-p~ and ~M-n~ bring back the last prompts.

A rewrite opens as a diff: ~y~ or ~C-c C-c~ accepts in one undo step, ~n~ or
~C-c C-k~ rejects, ~e~ opens ediff, ~r~ asks again with more to the
instruction. An answer opens below; ~C-c C-c~ there takes the question and
the answer into the chat's prompt. In a commit buffer ~M-g~ writes the
message from the staged diff.

* Setup
1. =claude= on PATH, signed in once.
2. For the chat:
   =npm install -g --prefix ~/.local @agentclientprotocol/claude-agent-acp=.
   Update it now and then, the same way with =npm update=: it can lag
   behind Claude Code, in its slash commands for one.
3. Install the hooks once with ~SPC l m h~: a terminal tells Emacs then when
   it finishes or needs you, for the modeline and the notification, and
   finished edits reload. It writes =~/.claude/settings.json= and keeps a
   =.bak=. The chat and the inline actions need nothing for it.
4. For gptel, optional: =ANTHROPIC_API_KEY=, or in =~/.authinfo.gpg=
   =machine api.anthropic.com login apikey password KEY=. With a key the
   inline actions go through gptel too.
5. On Wayland, =spectacle= takes the chat's screenshots; =doom doctor= says
   when it is missing.

Inside Claude's terminal, =/ide= shows the Emacs connection and =/mcp= lists
the tools.

* Configuration
- ~+ai-panel-width~ (72): the chat's and the terminal's side windows; 72
  columns are a readable line of prose, below 64 the terminal wraps a lot.
- ~+ai-auto-allowed-tools~: the Emacs tools that run without asking, in
  the chat and in the terminal. Never empty.
- ~+ai-tool-search-seconds~ (5): how long the project TODO search may
  hold Emacs; past it the tool answers with what it found.
- ~+ai-notify~ (t): the desktop notification; the faces
  ~+ai-status-permission~ and ~+ai-status-done~ colour the modeline entry.
- ~+ai-inline-backend~ (=auto=, else =gptel= or =claude-cli=),
  ~+ai-inline-model~ (=sonnet=, for the CLI), ~+ai-inline-context-lines~
  (30 lines each side of a region, to read), ~+ai-inline-pending~ (the
  region while its rewrite runs).
- ~+ai-claude-model~ for the terminal, ~+ai-gptel-directives~.
- ~+ai-claude-resize-delay~: how long a resized terminal window must hold
  still before Claude redraws for it. Its terminal follows the window
  down to 40 columns, vterm's own floor is 80.
- ~agent-shell-preferred-agent-config~ (Claude),
  ~agent-shell-session-strategy~ (=new=), ~agent-shell-context-sources~.
- ~claude-code-ide-use-ide-diff~, ~-enable-execute-code~.
- ~gptel-model~ (=claude-opus-5-5=, from gptel's own list), presets =deep=
  and =quick=.
- For MCP servers in gptel: set ~mcp-hub-servers~, then =M-x gptel-mcp-connect=.
