#+title:    :private uml
#+subtitle: PlantUML: completion, a live preview, and a template per kind

* Description
Doom's =:lang plantuml= brings the mode and the syntax checker. This
module adds the three things that make a diagram pleasant to write:

- *Completion*: =plantuml-lsp= through eglot, for keywords, directives,
  colours, skinparams and the C4 standard library, with hover and the
  diagnostics =plantuml -syntax= reports.
- *A preview beside the text*, which follows your typing.
- *Templates*, one per kind of diagram, on ~SPC m n~.

* The preview
Opening a diagram opens its drawing in a window on the right, which
keeps up as you type. The redraw waits for a pause, so a burst of keys
costs one drawing rather than one per key, and the typing never waits
for it: the server is asked without waiting for its answer, and the SVG
it sends back is drawn for the window by =rsvg-convert= in a process of
its own, sharp at any zoom, as core does for an SVG file. A diagram opened in the
background, by a search or an export, opens no window and starts no
server.

The diagram is fitted to the window and centred in it, and fitted again
when the window changes size. The window is one you can move into,
~C-w l~, to zoom a large diagram with =+= and =-=, fit it with =f= or pan
it with =h j k l=; the zoom and the place stay while you edit. ~q~ there
closes it, and it stays closed for that diagram until ~SPC m p~.

| Key       | What it does                          |
|-----------+---------------------------------------|
| ~SPC m SPC~ | the preview's menu                    |
| ~SPC m p~   | the preview, on or off                |
| ~SPC m P O~ | open it with every diagram, or not    |
| ~SPC m P r~ | draw it again now                     |
| ~SPC m P f~ | follow my typing, or wait to be asked |
| ~SPC m P F~ | draw as PNG instead of SVG            |
| ~SPC m e~   | write the diagram to a file           |

A diagram that does not parse leaves the last good drawing in place and
says what PlantUML complained about, so the preview never goes blank
while you are in the middle of a line; the line PlantUML names is marked
as an error, reached with the keys for the next problem.

The preview is coloured for the theme. PlantUML writes its background as
a CSS style on the SVG root and Emacs's renderer ignores that, so the
image arrives transparent over the Emacs background; on a dark theme
that would leave dark text on a dark background. ~+uml-preview-theme~ is
=auto=, which passes =-darkmode= when the frame is dark, so the diagram
comes back with light strokes and text. Set it to =light= to keep
PlantUML's own colours, or to the name of a PlantUML theme such as
="cyborg"=.

None of that touches the file, and ~SPC m e~ writes what you wrote.

* Why there is a server
PlantUML is a Java program. Rendering by running it costs about a second
each time, which is far too slow to follow typing. PlantUML can instead
serve its own =picoweb= HTTP server: the first drawing pays for the JVM,
every one after it costs about 30 milliseconds.

So this module starts =plantuml -picoweb= on the first preview and keeps
it. Measured here: 1.7 s for the first, then 0.03 s and 0.02 s. The
start happens in the background, so opening the first diagram of a
session does not freeze the editor while the JVM loads (it did, about
3 s); the drawing appears once the server answers. An export started
meanwhile waits for that same start.

| Key       | What it does                       |
|-----------+------------------------------------|
| ~SPC m s i~ | is it running, and on what port    |
| ~SPC m s r~ | restart it                         |
| ~SPC m s k~ | stop it; the next preview restarts it |

The port is =+uml-server-port=, 8135, or the first free one above it, so
two Emacs sessions do not fight over it.

* Templates
~SPC m n~ asks which kind and what to call it, copies the template and
opens it with the title filled in.

| Kind           | For                                          |
|----------------+----------------------------------------------|
| =sequence=       | who talks to whom, in order                  |
| =state=          | a state machine and its transitions          |
| =activity=       | a flow, with decisions and branches          |
| =component=      | boxes and the links between them             |
| =class=          | classes, fields and relationships            |
| =er=             | entities and their keys                      |
| =c4-context=     | C4 level 1: the system and who uses it       |
| =c4-container=   | C4 level 2: the parts it is deployed as      |
| =c4-component=   | C4 level 3: inside one part                  |
| =timing=         | signals against time, for a bus or a protocol |
| =bitfield=       | a register laid out bit by bit               |

They carry no styling on purpose: a =.puml= file here renders anywhere,
with no include and no shared theme to travel with it.

* What has to be installed
#+begin_src sh
sudo zypper in plantuml graphviz          # the renderer and the layout engine
go install github.com/ptdewey/plantuml-lsp@latest
ln -sf ~/go/bin/plantuml-lsp ~/.local/bin/plantuml-lsp
#+end_src

=graphviz= lays out every kind except sequence and timing, so without it
some diagrams work and others do not, which is a confusing way to be
broken. =rsvg-convert= (=brew install librsvg= on macOS; on openSUSE
=zypper what-provides rsvg-convert= names the package) draws the preview
in a process of its own; without it Emacs draws it, and a large diagram
pauses the typing. ~SPC h r d~ says what is missing.

The language server is optional. It is early software, so it is looked
for by name and everything here works without it; plantuml-mode's own
completion stays underneath.

* Configuration
- ~+uml-preview-format~ (=svg=), and ~+uml-preview-theme~ (=auto=), how the
  preview is coloured.
- The window, the pause before a redraw and whether it follows your
  typing are core's view, shared with SVG files and images:
  ~+core-view-side~, ~+core-view-width~, ~+core-view-idle~ (0.4 s),
  ~+core-view-follow~ and ~+core-view-on-open~.
- ~+uml-server-port~ (8135), ~+uml-server-start-timeout~ (30 s), and
  ~+uml-render-timeout~ (20 s), how long a drawing or an export waits for
  the server before it says so.
- ~+uml-templates-dir~, =$DOOMDIR/templates/uml/= by default.
