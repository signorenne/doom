#+title:    :private pascal
#+subtitle: Free Pascal and Lazarus, and Delphi sources read

* Description
Object Pascal, on the keys the rest of the config uses. What runs here
and what does not:

| Kind                   | Edit | Build | Run | Debug |
|------------------------+------+-------+-----+-------|
| Free Pascal (=.lpr=)     | yes  | fpc   | yes | gdb   |
| Lazarus (=.lpi=)         | yes  | lazbuild | yes | gdb |
| Delphi (=.dproj= =.dpr=)   | yes  | no    | no  | no    |

Delphi's compiler is Windows software and there is none on this
machine, so a Delphi project is read, navigated and edited here and
built in the IDE. The module says so rather than pretending: the panel
and ~SPC k m I~ both name the limit.

The module adds:

- the modes: =.pas=, =.pp=, =.lpr=, =.dpr=, =.dpk= and =.inc= in ~opascal-mode~,
  which is Emacs's own and speaks Delphi's dialect; =.lfm= and =.dfm= in
  ~conf-mode~, since a form is a property list and not code,
- what a build depends on, which is the Lazarus build mode, the widget
  set, the target, which program when there is more than one and the
  run arguments, kept in =.dir-locals.el= and carried by every command,
- two projection types, so ~SPC k b~, ~SPC k r~ and, for a Free Pascal
  project with =tests/tests.lpr=, ~SPC k t~ work here as they do in a
  CMake tree,
- fpc's =file(line,col) Error:= messages as jumps in the build buffer,
  which none of Emacs's own patterns read: ~RET~ opens one, ~]e~ goes to
  the next,
- the panel on ~SPC k m~, and a new project on ~SPC k n~,
- gdb through dape, reading the DWARF the build asks fpc for, and
  given the run arguments,
- pasls when it is installed, through eglot.

* Starting a project
~SPC k n~, from anywhere, then Pascal, then =console= or =lcl=.

- *console* is a Free Pascal command line program, the shape of the C++
  =app=: =src/options.pas= reads =--name=, =--count=, =--verbose=, =--help=
  and =--version= into a record, =src/greeter.pas= acts on it, the =.lpr=
  wires them and sets the exit code, and =tests/= holds fpcunit tests
  for both. =fpc -Mobjfpc -Sh -gw3 -FEbin= builds it into =bin/=.
- *lcl* is a Lazarus application with a window: the =.lpi= Lazarus reads,
  the =.lpr=, and a form as =mainform.pas= beside =mainform.lfm=. It carries
  a Debug and a Release build mode, range and overflow checks on in
  Debug, and DWARF 3 so gdb can read it.

Both get =.editorconfig=, =.gitignore= and =AGENTS.md=, the rules an agent
reads before touching the repo.

The project's name is the =.lpr='s and so the binary's, and it is
written into the program's =program= line, so it has to be a name Pascal
takes there: not a keyword (=label=, =file=, =set=), and not a unit the
template has or uses (=options=, =sysutils=, =tests=), which would be a
duplicate identifier. ~SPC k n~ says so before it makes anything. The
units themselves are named for what they hold, not for the project.

* What has to be installed
#+begin_src sh
sudo zypper in fpc fpc-src lazarus
#+end_src

- *fpc* is the compiler, *fpc-src* its sources: without the sources,
  go-to-definition stops at the runtime library.
- *lazarus* brings =lazbuild=, which builds a =.lpi= without opening the IDE,
  and the LCL the =lcl= template uses.

~SPC h r d~ says what is still missing.

** The language server
=pasls= puts Lazarus's CodeTools behind LSP. Nobody packages it, so it is
built once from source:

#+begin_src sh
git clone --depth 1 https://github.com/genericptr/pascal-language-server ~/src/pasls
cd ~/src/pasls/src
LAZARUSDIR=/usr/lib64/lazarus FPCDIR=/usr/share/fpcsrc ./build_fpc.sh
install -Dm755 ~/src/pasls/dist/x86_64-linux/pasls ~/.local/bin/pasls
#+end_src

Not =lazbuild pasls.lpi=: that wants two Lazarus packages registered
first and stops with "Broken dependency: lspserver". =build_fpc.sh= calls
fpc directly and needs neither.

=~/.local/bin= is already on =exec-path=, so a restart is all it takes.
The module finds Lazarus and the Free Pascal sources itself, at
=/usr/lib64/lazarus= and =/usr/share/fpcsrc= on openSUSE, and on macOS at
=/Applications/Lazarus= and under =/usr/local/share/fpcsrc=, and sets
=LAZARUSDIR=, =FPCDIR= and =PP= for the server; ~+pascal-lazarus-dir~ and
~+pascal-fpc-src-dir~ override that when a distribution puts them
elsewhere. On a Mac the commands above take those two paths, and the
binary lands in =dist/aarch64-darwin/=; a target written without its
system, =aarch64=, is built for this one.

Until pasls is there, a Pascal buffer has opascal-mode's own navigation,
imenu and the project's files, and no completion.

In a Lazarus project pasls is also handed the LCL's include directory:
it reads the project's unit paths from the =.lpi= but not the include
path of the LCL's own package, and failed on =lcl_defines.inc= in every
LCL unit, so nothing of the LCL, =TForm= among it, could be looked up.

** The formatter
=SPC c f= formats with JEDI Code Format, the formatter the Lazarus IDE runs
from Source > JEDI Code Format. Its command line version ships as source
inside Lazarus and is built once, like pasls:

#+begin_src sh
cp -r /usr/lib64/lazarus/components/jcf2 ~/src/jcf2
cd ~/src/jcf2/CommandLine/Lazarus && lazbuild jcf.lpi
install -Dm755 ~/src/jcf2/lib/CommandLine-x86_64-linux/jcf ~/.local/bin/jcf
#+end_src

A copy, because lazbuild writes its units beside the sources and
=/usr/lib64= is root's. ~SPC h r d~ says when it is missing.

* Formatting
The standard is what that formatter writes with the settings this
Lazarus ships for it, =components/jcf2/CommandLine/Lazarus/jcfsettings.cfg=:
two spaces, =begin= under the statement it belongs to, ~case~ labels one
level in, built-in types such as =integer= in lower case. The module's
=jcfsettings.cfg= is that file with five changes, each where the shipped
one undid what an author did on purpose or disagreed with the rest:

| Setting                     | Shipped | Here  | Why                                                   |
|-----------------------------+---------+-------+-------------------------------------------------------|
| =IndentLibraryProcs=          | True    | False | a program's routines went in two, a unit's did not    |
| =RemoveExpressionReturns=     | True    | False | an expression broken on purpose was joined back       |
| =RemoveProcedureDefReturns=   | True    | False | so was a parameter list                               |
| =KeepCommentsWithCodeInProcs= | True    | False | the comment above a nested routine went to the margin |
| =IndentVarAndConstInClass=    | False   | True  | =class var= sat with =private=, not with the fields       |

Lines too long are still broken. With =KeepCommentsWithCodeInProcs= off a
comment inside a routine stays where it is put, which Emacs's own
indentation has already put right. One quirk stays: in a program with no
=uses= clause, =$MODE= and =$H+= on one line are split in two.

A project's own =jcfsettings.cfg= wins over the module's, and saving
formats only in a project that has one, as C++ asks for a =.clang-format=:
someone else's code keeps its style until ~SPC c f~. Projects made with
~SPC k n~ carry the module's. The Lazarus IDE reads its own copy,
=~/.lazarus/jcfsettings.cfg=; copy this one there to format alike in both.

Typing agrees with the formatter: =TAB=, =RET= and ~=~ put a line where it
would. opascal-mode needed four corrections for that, in
=autoload/indent.el=: a routine after a =type=, =var= or =const= section
was indented into it, =begin= went one level past its =if=, a line inside
parentheses lined up under the first argument, and a condition broken over
lines went twenty columns out.

* Reading and writing Pascal
** What a buffer shows
opascal-mode coloured keywords, in lower case only, and among them words
that are also names: =E.Message= and a variable called =Index= were
keywords, =Begin= was not. The module's rules, =autoload/highlight.el=:

- keywords in any case; =read=, =write=, =index= and =default= only in a
  property, =virtual=, =override= and the like only after a header,
- ={$MODE OBJFPC}= as a directive, not a comment,
- types: the built-in ones, =TName=, =EName=, =IName=, and the type of a
  declaration; the names a =var= section or a parameter list declares,
- a routine's name where it is declared, its class apart, and a call
  where it is made; a field or method after a dot,
- numbers, =$FF= and =#13= included; =True=, =False=, =nil=; =Result=, =Self=.

With the cursor on =begin=, =try=, =case=, =repeat=, =record= or =class=, or
on the =end= or =until= that closes one, the other lights up the way a
matching parenthesis does.

** What completion offers
- pasls's completions, the words of the open buffers it did not offer,
  and the snippets whose key fits, in one list: before, the buffer's words
  showed only when pasls had nothing, so =Par= offered =ParamStr= and not
  the =Parsed= declared above it.
- In a =uses= clause, every installed unit by the name its source spells:
  =sysu= gives =SysUtils=. The LCL's in a Lazarus project only, and the
  project's own units. The list is read once and kept in Doom's cache.
- A new =.pas= or =.pp= file starts as a unit named after it, a new =.lpr=
  as a program.

The snippets, in =$DOOMDIR/snippets/opascal-mode/=; type the key and pick
it from the list, or =TAB= after it:

| Key     | What it writes                           |
|---------+------------------------------------------|
| =beg=     | =begin= ... =end;=                           |
| =ifb=     | =if= ... =then begin= ... =end;=               |
| =ife=     | =if= ... =then begin= ... =end else begin= ... |
| =forb=    | =for I := 0 to= ... =do begin= ... =end;=      |
| =forin=   | =for Item in Items do begin= ... =end;=      |
| =whileb=  | =while= ... =do begin= ... =end;=              |
| =repu=    | =repeat= ... =until= ...;                    |
| =caseof=  | =case= ... =of= ... =else= ... =end;=            |
| =tryfin=  | =try= ... =finally= ... =end;=                 |
| =tryexc=  | =try= ... =except on E: Exception do= ...    |
| =tryfree= | create, use in =try=, =Free= in =finally=      |
| =proc=    | a procedure                              |
| =func=    | a function                               |
| =cls=     | a class type with a property             |
| =rec=     | a record type                            |
| =prop=    | a property and its field                 |
| =wl=      | =WriteLn(...)=                             |
| =wlf=     | =WriteLn(Format(...))=                     |
| =test=    | an fpcunit test method                   |

No key is a word written for itself: with the popup's first candidate
taken by =RET=, a snippet called =begin= would expand at the end of every
=begin= typed.

* Configuration
- ~+pascal-build-mode~, ~+pascal-widgetset~, ~+pascal-target~, ~+pascal-main~
  and ~+pascal-run-args~: the per-project settings, all directory local.
- ~+pascal-templates-dir~, =$DOOMDIR/templates/pascal/= by default.
- ~+pascal-jcf-settings~, the formatter's settings where a project has
  none, the module's =jcfsettings.cfg=.
